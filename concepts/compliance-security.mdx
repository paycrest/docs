Paycrest is a payment routing and settlement protocol, not a financial institution. It never takes custody of funds: during an order they sit in the Gateway contract, which can only release them to the assigned provider or refund them to the sender. Most compliance responsibility sits with the participants.

## Compliance Model: Compliance at the Edges

Paycrest verifies who takes part, and each participant owns the compliance closest to them:

## KYB Requirements

### For Senders

Senders are companies or developers who integrate Paycrest to provide on- or off-ramp services to their users:

- Business verification (KYB) required before going live
- Register at [app.paycrest.io](https://app.paycrest.io) and complete the KYB process

### For Providers

Providers are businesses that supply fiat and stablecoin liquidity in both directions:

- Business verification (KYB) required before going live
- Live fiat rails in each corridor they serve, for paying out and receiving funds
- Ongoing compliance monitoring as a condition of continued participation

## Security

### Smart Contract Security

The Gateway contract is the only place funds are held, and only temporarily, in escrow:

- **Open-source contracts**: The Gateway contracts are public at [github.com/paycrest/contracts](https://github.com/paycrest/contracts).
- **Non-custodial escrow**: Funds are locked onchain until either (a) payout is verified and stablecoins are released to the provider, or (b) the order cannot be fulfilled and is refunded to the sender automatically.
- **Multi-signature governance**: Protocol parameter changes require multi-signature approval
- **Emergency pause**: The Gateway contract can be paused in a security incident

### API Security

- **API Key authentication**: Every API request requires a valid `API-Key` header
- **API Secret**: Used for webhook signature verification. Never expose it in client-side code
- **Webhook HMAC verification**: All webhooks include an `X-Paycrest-Signature` header using HMAC-SHA256, allowing receivers to verify payload authenticity
- **TLS required**: All API communication over HTTPS; never disable SSL verification in your HTTP client

### Data Protection

- **Encrypted recipient data**: Bank account and mobile wallet details are encrypted in transit and at rest
- **Minimal data retention**: The protocol stores only what is needed for routing, settlement and compliance

## Governance

Protocol changes are ratified by the Paycrest Core Multisig. As the protocol matures, governance is intended to move toward broader, community-led decision-making. See the [Decentralization Path](/introduction#decentralization-path).

## Pricing & Sender Fees

Every order gets **one all-in rate**, quoted live by the Paycrest Sender API. Senders pay no separate Paycrest fee.

- **Rate**: Paycrest's fee is built into the provider's rate, never added on top.
- **Transaction fee**: Covers the gas the aggregator pays to create and settle the order. By default it comes out of the sender fee; the integrating app can pass it to its customers instead.
- **Sender fee (optional)**: Set by the integrating app and settled onchain in the same transaction as the order.
- **No offchain billing**: There is nothing to invoice or reconcile.

Apart from the transaction fee and any sender fee, nothing is added to the quoted rate. Planning high volumes? Talk to us at [support@paycrest.io](mailto:support@paycrest.io).
